# ReleaseProof Successor v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, verify, deploy, and prove a frozen ReleaseProof v2 successor with safe expiry, prompt-injection resistance, deterministic reasons, complete provenance UI, and a current fixed evidence package.

**Architecture:** Replace the repository's current contract source with schema v2 while preserving every deployed predecessor through versioned manifests and Git history. The contract remains the only outcome authority; validators independently evaluate untrusted pinned Markdown, while all persisted reasons are contract-generated. The existing React/genlayer-js frontend keeps its MetaMask/Snap connector and gains v2 record parsing, provenance display, and Studionet explorer links.

**Tech Stack:** Python 3.14, py-genlayer pinned runtime, gltest/glsim, TypeScript 7, React 19, genlayer-js 1.1.8, Vitest, Testing Library, Playwright, Vite, Vercel.

## Global Constraints

- Contract schema is exactly `releaseproof-case-v2`; policy remains exactly `reproducibility-v1`.
- Binding prefix is exactly `releaseproof-case-v2|reproducibility-v1|submit_case|`.
- v1 contract `0x946BC9B19BD971CBefb56845b5825FB7B9f6b183` remains immutable read-only history.
- v2 is `INTENTIONALLY_FROZEN` with no owner, upgrade, edit, delete, or result override.
- Expiry after 30 days deterministically writes terminal `UNRESOLVED` without web or LLM calls.
- No LLM-generated free-text is persisted; reasons are generated by contract code.
- Artifact Markdown is untrusted data; prompts must explicitly ignore instructions contained inside it.
- Production frontend stays on v1 until v2 source/schema/readback verification and an explicit user-confirmed cutover.
- No GitHub push, Studionet deployment, wallet write, Vercel environment mutation, or Vercel deployment occurs without the GenLayer action-time identity and confirmation gate.
- All behavior changes use red-green TDD, one behavior per test, with fresh full verification before any completion claim.
- Do not commit secrets, `.env`, virtual environments, `node_modules`, build output, browser artifacts, chat logs, or local instruction files.
